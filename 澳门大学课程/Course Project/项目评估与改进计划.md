## 3. Task 2 / Task 3 将来会踩的坑

### 3.1 硬件与环境的硬约束

- **8GB 显存放不下 7B 及以上模型**，fp16 权重就要 14GB 起步。本项目不使用这一档模型。
- **本项目单次编辑的峰值显存约 10–11GB**（EasyEdit 官方默认配置：ROME 10GB、MEMIT 11GB）。原因是复现 ROME/KnowEdit 要求 `fp16: False`，fp32 下 GPT-2 XL 权重就是 6.2GB，再加激活、反传缓冲和多份 6400×6400 矩阵。**8GB 笔记本会 OOM**，必须用 Kaggle T4 / Colab T4。模型权重只有 3GB 不代表能跑完一次编辑。
- 全参数微调约需 24GB（`1.5e9 × 16B`），超出 8GB；但**只更新单层 / 多层（FT-L / FT-M）**时优化器只有 0.2–1GB，可行。
- 真正卡住的不是显存，而是**时间**：训练类基线（SERAC / MEND / AdaLoRA）在小机器上要跑很久，必须砍掉。

### 3.2 实验规模（原计划里最大的坑）

原计划 = 5 个评测维度 × 4 组消融 × 4 个编辑数量级 × 3 个编辑顺序 = 几十到上百组实验，5 周跑不完。必须按第 5 节收缩。

### 3.3 学术层面的风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 改进点与 AlphaEdit 重叠 | null-space 投影是 AlphaEdit 的原创点，Q&A 一句"这不就是 AlphaEdit 吗"很难答 | 把贡献定位为"在小模型上测量局部性约束的收益与代价"（见 2.G3 / 2.G6） |
| 小模型结果可能不显著 | 1–1.5B 模型事实知识有限，编辑前后差异可能很小 | 先用固定小子集（100 条）看趋势；保留 no-edit 作下界；把"改不动"本身写成发现 |
| 跨模型对比不干净 | GPT-2 XL 与原文的 Llama2-7b-chat 不可直接比较 | 只做趋势对照，明确说明差异来源 |
| 评测脚本要自己拼 | KnowEdit 的指标在 EasyEdit 里部分现成 | 第一周就写好统一脚本并冻结 prompt 与答案匹配规则 |

### 3.4 交付与流程风险

- 最终报告 **11/17 23:55** 截止；"Implementation & All Materials" 提交槽显示的是 **11/17 00:00（凌晨）**，建议按 **11/16 晚上** 全部交完。

- 课堂展示 **11/17 和 11/24 必须出席**，缺席扣分；每组 4 分钟汇报 + 1 分钟 Q&A。
- 预录视频 **5 分钟，所有成员都要出镜**，还要上传到公开平台（如 YouTube）并填共享表格登记链接——**最容易漏的一件事**。

## 4. 全部在本机跑：方案与可行性

### 4.1 各方法在本机的可行性

| 方法 | 笔记本 8GB 可行性 | 说明 |
|---|---|---|
| ROME | ⚠️ 需 16GB | 官方默认配置 **10GB**。协方差是纯前向，官方提供预计算统计文件可跳过。→ 放 Kaggle T4 |
| MEMIT | ⚠️ 需 16GB | 官方默认配置 **11GB**。需要多层协方差，1.5B 规模每层约 25MB。→ 放 Kaggle T4 |
| AlphaEdit | ⚠️ 需 16GB+ | MEMIT 加零空间投影，另需计算并保存协方差矩阵，峰值 ≥ MEMIT。→ 放 Kaggle T4，且排在最后验证 |
| FT-L / FT-M | ⚠️ 勉强可行 | 只更新单层或多层，优化器 0.2–1GB。慢但不爆显存 |
| AdaLoRA | ❌ 建议砍掉 | 需要大量训练轮次与数据，时间成本过高 |
| MEND | ❌ 砍掉 | 元训练要全参数反传 + Adam，1.5B 约 24GB |
| SERAC | ❌ 砍掉 | 要另训一个反事实模型，8GB + Windows 下非常痛苦 |
| 7B–8B 级模型 | ❌ 不可行 | fp16 权重 14–16GB。本项目不使用 |

### 4.2 三个环境坑（第一周就要验证）

1. **PyTorch 与 50 系显卡的兼容性**：RTX 50 系（Blackwell / sm_120）需要 CUDA 12.8+ 与 PyTorch 2.7+；EasyEdit 是老仓库，按官方 requirements 装会装到旧版 PyTorch，可能直接报 "no kernel image is available"。
   → 装最新的 cu128 版本 PyTorch，不要照搬版本号；或改用 Kaggle（见 4.3）。
2. **Windows 环境**：EasyEdit 依赖的部分库在 Windows 上容易出问题。→ 用 WSL2，或本地只写代码、实验搬到 Kaggle。
3. **磁盘与网络**：数据集 + 预计算统计 + 模型权重合计几 GB 到十几 GB，建议预留 50GB。

### 4.3 算力安排：笔记本 + 免费云算力

既然申请不到 3090 工作站，就用老师已经给的免费渠道顶上：

| 渠道 | 规格 | 额度 | 用途 |
|---|---|---|---|
| **Kaggle Notebooks** | T4 ×2（每张 16GB）或 P100×1 | 每周 **30 小时** | **主力：跑批量实验** |
| Google Colab | T4 ×1（16GB） | 单次 12 小时 | 备用 |
| 本地笔记本 | RTX 5070 8GB | 无限 | 写代码、调试、小样本、出图、写报告 |

好处：T4 是 16GB，跑 GPT-2 XL 绰绰有余；**T4 是老架构，与任何现代 PyTorch 都兼容，4.2 节那个 50 系显卡的坑在 Kaggle 上不存在**；每周 30 小时 × 5 周 = 150 小时，远超所需。

注意：Kaggle 单次会话有 9–12 小时上限，工作目录约 20GB，pip 安装需要打开联网开关；两边用同一份代码 + 固定随机种子。

### 4.4 模型选择（已确定）

**主模型：GPT-2 XL（1.5B）　选做对照：TinyLlama-1.1B-Chat**

选 GPT-2 XL 的五个理由：

1. **它就是 ROME 原论文用的模型**，原版仓库和 EasyEdit 都带官方超参配置，属于"下下来就能跑"。
2. **官方提供预计算好的协方差统计**，最耗时的一步可直接下载，不用自己跑十万条样本。
3. 它是 **base 模型、没有对话模板**，评测直接算事实 token 的概率，不用跟 chat 模板和答案抽取较劲，复现结果稳定得多。
4. 权重体积小（fp16 约 3GB），但**默认配置下编辑峰值约 10–11GB，笔记本 8GB 跑不动**——所以它是"能在免费 Kaggle T4 上轻松跑"的模型，而不是"能在本机跑"的模型。
5. 若被问"为什么用这么老的模型"，标准答案：**ROME 原文就在它上面做，CounterFact 数据集也是为它建的**，这样才能真正对标原文数字。

TinyLlama-1.1B-Chat 作为**选做**第二模型：价值是提供跨模型家族的对照；但需要自己按 Llama 配置改层号与超参，有额外时间成本。**时间不够就直接砍掉，不影响交付完整度。**

| 模型 | 参数量 | fp16 权重 | EasyEdit 现成配置 | 本机可行性 | 定位 |
|---|---|---|---|---|---|
| GPT-2 medium | 355M | ~0.7GB | ✅ 有 | ✅ 轻松 | 只用来调通流程，不出结果 |
| **GPT-2 XL** | **1.5B** | **~3GB** | **✅ 有 + 可下载预计算统计** | ⚠️ **Kaggle T4 可跑；本机 8GB 会 OOM** | **主模型** |
| TinyLlama-1.1B-Chat | 1.1B | ~2.2GB | ⚠️ 需自己改 | ✅ 轻松 | **选做对照** |
| Llama-3.2-1B-Instruct | 1B | ~2.5GB | ⚠️ 需自己配 | ✅ 轻松 | 备用 |
| Phi-2 / Gemma-2-2B | 2–2.7B | ~5.2–5.4GB | ❌ 架构特殊 | ⚠️ 紧张 | 不建议 |
| 7B–8B 级模型 | 7–8B | 14–16GB | ✅ 有 | ❌ 不可行 | 不使用 |

**实操提醒**
- EasyEdit 支持哪些模型，装好后直接看它 `hparams/ROME/` 目录下的 yaml 列表，比查文档准。
- 无论用哪个模型，**第一件事都是"只跑一条编辑"**：确认模型能答对、编辑后能改口。改不动要早发现、早换。

### 4.5 纯笔记本：时间量级与注意事项

**结论：可以全程只在笔记本上跑完**（前提是按第 5 节砍范围）。

5070 Laptop 8GB + GPT-2 XL 的粗略时间量级：

| 任务 | 量级 |
|---|---|
| 环境搭好 + 跑通一次 ROME 编辑 | 半天到 1 天（主要是装环境） |
| 一条 ROME / MEMIT 编辑 | 秒级到 1 分钟 |
| 100 条测试样本评测 | 几分钟 |
| 100 次连续编辑 + 评测 | 10–40 分钟 |
| 自算协方差统计（10 万条，纯前向） | 几十分钟到 2 小时（**用官方文件可跳过**） |
| AlphaEdit 零空间投影 | 每次编辑增加几十秒（特征分解可在 CPU） |

即主要实验一轮是"几小时"级别。花时间的是调流程，不是等显卡。

挂机注意事项：

1. **关掉浏览器和视频**：Windows 会占显存，关掉后可用显存能回到 7GB 左右。
2. **断点续跑**：每跑完一条编辑就写盘（jsonl），支持中断后继续 —— 笔记本断电、休眠、系统更新的概率远高于服务器。
3. **关掉自动睡眠与自动更新**，否则一晚上白跑。
4. **散热与降频**：长时间跑会降频，切成一两小时一段。
5. **用 fp16 + 小 batch**，不要为了快而调大 batch。
6. **重复性的批量实验放 Kaggle**，笔记本留出来写报告。
7. **CPU 兜底**：万一张量环境装不通，32GB 内存足够把 GPT-2 XL 放内存里用 CPU 跑，慢但能出结果，小样本实验完全够用。
