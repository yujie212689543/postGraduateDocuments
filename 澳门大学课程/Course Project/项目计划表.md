### 4.1 减重地板（不可越过）

低于这条线，是"掉分"而不是"减负"：

- 至少 **2 个方法**（不能只剩 1 个）
- 至少 **1 个 unedited 基线**
- 必须保留 **旧编辑保留率（retention）** 与 **locality**
- 至少 **1 条固定编辑顺序**

### 4.2 减重地板之外的三件不可砍之事

1. 旧编辑保留率——这是课题的智力核心。
2. locality——这是"知识编辑"区别于"直接微调"的关键指标。
3. no-edit 基线——没有它，所有数字都说不清是编辑带来的还是模型本来就有的。

### 5.2 四条由此得出的结论

1. **正式 run 全部放 Kaggle**。三台本地机器只有 1 台能跑编辑（12GB），且实测空闲仅 9.8GB < ROME 所需 10GB；MEMIT 与 AlphaEdit 本机无望。
2. **最大的减重是"砍环境"，不是"砍实验"**：只在 M2 装完整深度学习环境 + EasyEdit；M3 装同一套 cu128 用于 gpt2 小模型开发；M1 完全不需要 torch（只用 pandas / matplotlib 做数据处理与出图）。省 2–3 天环境工时。
3. **调试不上 Kaggle，额度只留给正式 run**。当前范围 4 组正式 run 约需 2–6 小时 GPU，**1 个账号即够**。
4. **同一方法的全部 run 必须放同一台机器**：三台本地机器 cc 为 6.1 / 12.0 / 12.0，Kaggle 是 7.5，跨机器数字不可作同条件比较。

## 6. 跨机器实验规则（摘要）

核心三条：

1. **run 独立可重跑**：任意一台机器，有 commit 号 + requirements + manifest 就能重跑。
2. **只在一处改代码**：固定一台当代码主库，其余两台只拉取运行，不许各自改。
3. **每个 run 落盘 `metrics.json`**：config、git commit、依赖版本、manifest 哈希、seed、指标、显存峰值、耗时、device。
