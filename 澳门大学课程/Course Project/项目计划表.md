## 3. 当前范围：减重版最小可行方案

| 项目 | 内容 |
|---|---|
| 模型 | GPT-2 XL（1.5B），EasyEdit 官方配置 |
| 方法 | no-edit（基线）+ ROME + MEMIT；AlphaEdit 视资源追加 |
| 数据集 | ZsRE（主）；WikiData_counterfact 时间富余再加 |
| 编辑规模 | 每条序列 100 次连续编辑；checkpoint 取 1 / 10 / 100 |
| 顺序 | 1 条主顺序 + 1 条校验顺序（只对主方法与主数据集） |
| 必做指标 | 编辑成功率、locality、旧编辑保留率（retention） |
| 条件指标 | portability（仅在标注完整的子集上报，缺失记 N/A） |
| 运行组数 | 约 **6–9 组**（原始方案 18 组） |
| 预计 GPU 时间 | 约 5–12 小时 T4 |
| 结论口径 | "在 ZsRE 上、GPT-2 XL 下，按固定协议复现并比较三种方法；不主张新算法" |

**预期工作量**：全组约 105–145 人时；其中关键路径（环境 + runner + 状态管理 + 指标）约 30–40 人时。
换算：3 人 × 5 周 × 每周 7–10 小时 ≈ 每天 1–1.5 小时。

### 4.1 减重地板（不可越过）

低于这条线，是"掉分"而不是"减负"：

- 至少 **2 个方法**（不能只剩 1 个）
- 至少 **1 个 unedited 基线**
- 必须保留 **旧编辑保留率（retention）** 与 **locality**
- 至少 **1 条固定编辑顺序**

### 4.2 减重地板之外的三件不可砍之事

1. 旧编辑保留率——这是课题的智力核心。
2. locality——这是"知识编辑"区别于"直接微调"的关键指标。
3. no-edit 基线——没有它，所有数字都说不清是编辑带来的还是模型本来就有的。

### 5.3 关键硬件事实（勿忘）

| 方法（GPT-2 XL 默认配置） | 峰值显存 |
|---|---|
| FT | 7GB |
| ROME | **10GB** |
| MEMIT | **11GB** |
| MEND | 13GB |
| AlphaEdit | ≥ MEMIT，可能 13GB+ |

- 复现 ROME 在 KnowEdit 上的结果**必须 `fp16: False`**，不能靠半精度压显存。
- 50 系显卡（compute_cap 12.0）需 CUDA 12.8+ / cu128 版 PyTorch；T4（7.5）无此问题。

## 6. 跨机器实验规则（摘要）

详见《跨机器实验编排-本地与Kaggle.md》。核心三条：

1. **run 独立可重跑**：任意一台机器，有 commit 号 + requirements + manifest 就能重跑。
2. **只在一处改代码**：固定一台当代码主库，其余两台只拉取运行，不许各自改。
3. **每个 run 落盘 `metrics.json`**：config、git commit、依赖版本、manifest 哈希、seed、指标、显存峰值、耗时、device。
