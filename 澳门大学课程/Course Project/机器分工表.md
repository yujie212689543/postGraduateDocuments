## 2. Kaggle 环境配置要求（照做）

1. **每次会话开头固定这几步**（Kaggle 环境每次重置）：
   - 打开 notebook 右侧 **Internet** 开关
   - `!pip install -r requirements.txt`（或直接 clone EasyEdit 仓库）
   - 记录本次的包版本，写进 `metrics.json`
2. **不要覆盖 Kaggle 自带的 PyTorch。** T4 是 sm_75，自带 torch 已经支持；强行装 cu128 反而可能引入问题。**cu128 只在柯冠宇的 50 系机器上需要。**
3. **`requirements.txt` 分两份**（同一个文件会互相打架）：
   - `requirements-kaggle.txt`：不给 torch 指定索引（用自带的）
   - `requirements-local.txt`：`--index-url https://download.pytorch.org/whl/cu128`
   - 其余（transformers / datasets / EasyEdit 依赖）版本号两边**必须一致**
4. **gpt2-xl 权重别每次重下。** 每次会话下载约 6GB 很浪费时间。做法：第一次下完后打包上传成 **Kaggle Dataset**，之后挂载复用。
5. **结果落盘**：写入 `/kaggle/working` → 点 **Save Version**。否则会话结束就没了。
6. **一个 session 只跑一个 run。** 单次上限 9–12 小时，别塞多个。
7. **额度优先给正式 run**，调试和探索尽量放本地 12GB 机器。

## 3. 因为硬件现实，报告要再砍一档（减重清单）

### 3.1 锁定后的范围

| 项目 | 原方案 | **锁定方案（本次减重后）** |
|---|---|---|
| 数据集 | ZsRE + WikiData_counterfact | **只保留 ZsRE** |

## 4. 分工表

### 4.1 第一层：角色分工（与方案无关，现在就能定）

> 这一层不依赖"最后跑几组实验"，所以**现在定下来不会白费**。

| 角色 | 职责 | 建议承担 | 需要的机器 |
|---|---|---|---|
| **A 实现与运行** | 环境、runner 脚本、顺序编辑状态管理、跑实验 | **柯冠宇** | 12GB 本地机 + Kaggle |
| **B 数据与评测** | 数据清单 manifest、标注覆盖率核查、指标口径、结果抽查、CPU 侧算分 | **蔡小诚** | MX350 机器（纯 CPU 足够） |
| **C 分析与写作** | 图表、报告、PPT、视频剪辑、提交管理；兼**代码主库**与数据仓库 | **本机（G16）** | ROG Strix G16（8GB，32 线程，近 1TB 磁盘） |

**关键纪律**：三人共用一套代码与一份 `requirements`，**只由 A 修改代码**，B、C 只拉取使用。三份脚本 = 三倍调试 = 结果无法比较。

### 4.2 第二层：run 分配（等 pilot 后再填，现在只是预留方案）

正式编辑 run 只有 **4 组**：`ROME×顺序1`、`ROME×顺序2`、`MEMIT×顺序1`、`MEMIT×顺序2`。

**默认分配（推荐）**：

| run | 机器 | 账号 | 预计耗时 |
|---|---|---|---|
| no-edit 基线评测 | Kaggle | 任意 | 几分钟 |
| ROME × 顺序1 | Kaggle T4 | 账号 1（蔡小诚） | 约 0.5–1.5 h |
| ROME × 顺序2 | Kaggle T4 | 账号 1（蔡小诚） | 约 0.5–1.5 h |
| MEMIT × 顺序1 | Kaggle T4 | 账号 2（柯冠宇） | 约 0.5–1.5 h |
| MEMIT × 顺序2 | Kaggle T4 | 账号 2（柯冠宇） | 约 0.5–1.5 h |
| AlphaEdit 尝试（可选） | Kaggle T4 | 账号 3（本机 / G16） | 视情况 |

**角色对应关系（最终版）**

| 人 | 机器 | 角色 | Kaggle 账号 | 承担 run |
|---|---|---|---|---|
| 柯冠宇 | Legion Y9000P（12GB，唯一本地 GPU） | **A 实现与运行** | 账号 2 | MEMIT × 2 顺序 |
| 蔡小诚 | MateBook（MX350，纯 CPU） | **B 数据与评测** | 账号 1 | ROME × 2 顺序 |
| 本机（G16，8GB，32 线程） | ROG Strix G16 | **C 分析与写作**（兼代码主库、数据仓库） | 账号 3 | AlphaEdit 尝试 + 备用 |

**一条硬规则**：

> **同一个方法的全部 run 必须放在同一台机器（同一个平台）上。**
> 绝不允许"ROME 顺序 1 在本地、顺序 2 在 Kaggle"——那样两个顺序的差异里混进了机器差异，结论就废了。

**备用方案（Kaggle 额度不够时）**：把**某个方法的两个顺序整体**搬到柯冠宇的 12GB 本地机器上跑。前提是那个方法在本地跑得起来——按实测空闲显存 10018 MiB 算，**ROME 临界、MEMIT 基本会 OOM**，所以备用方案事实上只对 ROME 可行。

## 5. 每台机器负责什么 + 注意事项

### 机器 1｜柯冠宇（5070 Ti 12GB）—— 本地验证机

**负责**：
- 搭本地环境、跑通"一次 ROME 编辑"（这是整个项目的第一个里程碑）
- 短序列调试（1 条 / 10 条），验证状态管理与指标口径
- 出图前的小规模复算
- Kaggle 上的正式 run（用他的账号）

**注意事项**：
1. **必须先装 Python 3.11 或 3.12**，现在的 3.14.4 对 PyTorch 太新，可能没有对应轮子。
2. **必须装 cu128 版 PyTorch**（compute_cap 12.0）：
   `pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128`
   装成默认轮子的话，报错会出现在**运行时**（"no kernel image is available"），很容易误判成代码 bug。
3. **实测只有 10018 MiB 空闲显存**：ROME（约 10GB）临界，MEMIT（约 11GB）大概率 OOM。跑之前先关掉浏览器、视频、微信等占显存的程序。
4. **C 盘只剩 48.3 GB**，模型缓存一定要重定向：`$env:HF_HOME = "D:\hf_cache"`。
5. 没有 WSL2 → 只能用原生 Windows；如果某个依赖只有 Linux 版，直接改到 Kaggle 上跑，别折腾。
6. 长跑时用性能模式 + 垫高散热，避免降频。

### 机器 2｜蔡小诚（MX350 2GB）—— 数据与评测机

**负责**：
- 生成并冻结 `manifest.json`（100 条样本 ID）
- 检查 KnowEdit 各字段与标注覆盖率（locality / portability 标注缺多少）
- **CPU 侧指标计算**：对 Kaggle 跑完保存下来的输出算分，完全不碰 GPU
- 报告撰写、参考文献核对、提交材料管理

**注意事项**：
1. **不要升级显卡驱动、不要尝试在本机跑编辑实验。** 2GB 显存 + CUDA 10.2，无论怎么弄都跑不了本项目。
2. 需要先装 **Python（CPU 版即可）**——本机目前完全没装 Python。CPU 侧的数据处理与算分不需要 GPU 驱动。
3. **磁盘缓存放 E 盘**（C 盘剩 95.6 GB，E 盘剩 162.5 GB）：`$env:HF_HOME = "E:\hf_cache"`。
4. 内存只有 15.8 GB 且焊死不可扩展 → 不要在本机读超大文件，用流式读取或抽样。

### 机器 3｜本机（ASUS ROG Strix G16，5070 Laptop 8GB）—— 开发与写作机

**负责**：
- **代码主库**：runner、指标函数、prompt 模板都在这里写（唯一允许改代码的地方）
- 用 **gpt2 / gpt2-medium**（小模型）验证整条流水线，不需要大显存
- **CPU 侧重活**：32 线程，适合批量算指标、生成图表数据、处理大数据文件
- 报告、PPT、视频与提交管理（角色 C）
- 用他的 Kaggle 账号承担第三份算力

**注意事项**：
1. **8GB 显存跑不了 ROME / MEMIT 的正式实验**，别在这里试 —— 试了也是 OOM，浪费一天。
2. **必须装 cu128 版 PyTorch**（cc 12.0），命令同柯冠宇那台。
3. 现有 Python 3.14.5 对 PyTorch 偏新，**另装 Python 3.11/3.12** 专用于本项目。
4. 有 AMD 核显 → 跑 GPU 任务前设 `CUDA_VISIBLE_DEVICES=0`，否则可能落到核显上报错。
5. **`HF_HOME` 放 D 盘或 F 盘**（C 盘剩 279.8 GB 其实也够，但 E 盘只有 9.9 GB，千万不要设到 E）。
6. 这台机器磁盘最大（近 1 TB），**可以让它兼做"数据仓库"**：全组的数据集、模型缓存、跑完的日志都可以在这里留一份。

### Kaggle（云）—— 正式算力主力

**负责**：**全部 4 组正式编辑 run**，以及 AlphaEdit 的可行性尝试。

**注意事项**：
1. **只有 1 个 Kaggle 账号是确认的**（蔡小诚的）。**请务必补齐另外两个**——额度按账号算，1 个账号 30 小时/周，3 个就是 90 小时/周。
2. 用 Kaggle **自带的 PyTorch**，别装 cu128（T4 是 sm_75，自带版本已支持）。
3. 打开 **Internet** 开关，否则 pip 装不了东西。
4. 结果写进 `/kaggle/working` 后**一定要 Save Version**。
5. gpt2-xl 权重每次重下约 6GB → 打包成 Kaggle Dataset 复用。
6. 一次会话 9–12 小时上限，**一个 session 只跑一个 run**。
