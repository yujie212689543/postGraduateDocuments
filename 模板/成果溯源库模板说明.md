# 成果溯源库 通用模板说明文档

> **用途**：当你需要针对某份申报书/申请书/参赛材料的各项要点，从一堆零散的原始材料中提取证据并归集时，可使用本模板指导 AI（或手动）生成一份「成果溯源库」。
>
> **核心理念**：**保留原文、标注来源、不做改写、不做总结、只做证据归集。**

## 一、什么是成果溯源库

**成果溯源库**是一个**证据索引文档**，它的作用是：

- 将某一份申报表（或申请书、参赛表）中的每一个填写要点，**逐项**从零散的原始材料（docx、pdf、md 等）中找出**原文证据**
- 以 **「证据原文 + 来源文件 + 位置定位」** 的三列表格形式，将证据归集起来
- 让申报表的填写者能**一站式**找到每个格子该填什么、依据是什么

它**不是**一份总结、不是一份改写、不是一份分析报告——它是一份**「证据地图」**。

### 适用场景

| 场景 | 示例 |
|------|------|
| 奖项申报 | 网络强省建设优秀实践成果申报、科技进步奖申报 |
| 项目参赛 | 数据要素应用创新大赛、创新创业大赛 |
| 资质认证 | 高新技术企业认定、专精特新申报 |
| 课题验收 | 科研项目结题报告、成果鉴定 |

## 二、核心原则

```
┌─────────────────────────────────────────────┐
│           成果溯源库 五条铁律                  │
├─────────────────────────────────────────────┤
│ 1. 保留原文 —— 直接引用，不 paraphrase        │
│ 2. 标注来源 —— 每段证据都标明原始文件          │
│ 3. 定位精准 —— 注明章节、段落、页码             │
│ 4. 不做改写 —— 不总结、不润色、不合并           │
│ 5. 诚实标记 —— 找不到就标 ⚠️ 缺失              │
└─────────────────────────────────────────────┘
```

### 详细说明

1. **保留原文**：直接从原始材料中**逐字复制**原文，不要转述、不要概括、不要合并多条原文。原文如果是英文就保留英文。
2. **标注来源**：每条证据必须标记出自哪个文件。文件名称应和材料清单中的编号/名称一致。
3. **定位精准**：尽量精确到文件中的章节标题或段落位置。无页码的电子文档使用「章节标题层级路径」定位（如 `二、项目介绍-三、应用价值`）。
4. **诚实标记**：如果某条证据原文中有错别字或格式问题，保留原样，可在旁边用 `[原文如此]` 或 `[sic]` 标注—不要默默修正。
5. **缺失标记**：如果申报表要求的某个要点在所有材料中都找不到对应内容，**不要编造**，而是用 ⚠️ 标记出来，说明「在现有材料中未找到」。

## 三、标准文档结构（骨架）

以下是成果溯源库的标准章节结构。**根目录**（一级标题）对应申报表的大板块，**子目录**（二级/三级标题）对应申报表的具体填写项。

```
# 成果溯源库

> **对应申报项目**：[项目名称]
> **溯源依据**：[申报表名称及版本]
> **生成日期**：[YYYY-MM-DD]
> **材料清单**：
> 1. `文件名.扩展名` — 文件简要说明
> 2. `文件名.扩展名` — 文件简要说明
> ...
```

## 四、各部分详细写法说明（举例）

### 4.1 文档头部元信息块

使用 `>` 引用块，在标题下方依次列出：

```
> **对应申报项目**：[填写具体的项目/成果名称]
> **溯源依据**：[申报表的完整名称] 结构
> **生成日期**：[YYYY-MM-DD]
> **材料清单**：
> 1. `文件名.扩展名` — 一句话说明该文件的内容和与本项目的关系
> 2. `文件名.扩展名` — 同上
```

- **材料清单**：列出所有提供给 AI 的原始材料文件。每个文件配一句简短说明，说明它与当前申报项目的关联。如果是空白模板，应注明「尚未填写」。
- **文件命名**：文件尽量保留原名，方便对照。

### 4.2 基本资料板块（一、基本情况）

对应申报表中关于「项目名称」「申报单位」「联系人」「成果概述」等基本信息的填写项。

**写作要点**：
- **证据原文**：优先引用申报表中其他已有材料中的完整句子；如有多个来源可交叉验证，可多行显示
- **单位介绍类长文本**：可整段引用，无须裁剪
- **未填写项**：如某字段在所有材料中均空白，在末尾单独用 `## ⚠️ 申报表中尚未填写的内容` 小节列出

### 4.3 针对性板块（二、成果针对性 / 需求分析）

对应申报表中关于「必要性」「痛点」「难点」「解决路径」的描述。

**写作要点**：
- 如有多个材料都描述了痛点，逐一列出，**不合并、不选取"最优"表述**
- 可分设子节：行业痛点、政策背景、工作难点、解决路径

### 4.4 创新性板块（三、创新性）

对应申报表中关于「技术创新」「模式创新」「应用创新」的描述。

**写作要点**：
- 按创新类型分设子节（3.1 技术、3.2 模式、3.3 架构...）
- 技术层面如有多个维度（数据、模型、算力、安全、国产化），可进一步拆分三级标题
- 同一创新点在不同材料中的表述差异，**全部保留**并列展示

### 4.5 实效性板块（四、实效性 / 应用成效）

对应申报表中关于「应用规模」「具体场景」「经济社会效益」的描述。

**写作要点**：
- **应用场景**建议逐一列出（场景一、场景二...），每个场景一个独立表格
- 如有多个产出物（如报告、截图等），可在场景下设立详情子节详细列出
- **量化数据**（如接入 XX 个委办局、支撑 XX 个智能体）优先突出

### 4.6 推广性板块（五、可复制推广性）

对应申报表中关于「推广价值」「可复制性」「标准化」的描述。

**写作要点**：
- 突出运营模式、标准化接口、生态共建等体现可复制的证据
- 如有「样板」「范本」「模式输出」等关键词，优先引用

### 4.7 材料问题标注板块（六、╳ 材料问题标注）

**这是成果溯源库的特色板块**，用于诚实记录所有存在的问题。

**包含内容**：
1. **材料关系说明**：解释多份材料之间的关联（如 B 文件是 A 文件的附件、C 报告是基于 D 平台能力生成的等）
2. **材料中缺失的内容**：按申报表结构逐一核对，列出所有找不到证据的要点，注明「缺失」
3. **关于页码的说明**：如原始材料无固定页码，说明本库的定位方式（如使用章节标题路径）

## 五、证据表格格式规范

### 5.1 标准三列表格

```markdown
| 证据原文 | 来源文件 | 位置/章节 |
|----------|----------|-----------|
| "引用的原文内容..." | `文件名.扩展名` | 章节标题路径或页码 |
```

### 5.2 填写规范

| 列 | 规范 |
|---|------|
| **证据原文** | 1. 使用**中文引号**（「」或 ""）包裹原文内容<br>2. 保留原文原貌，包括标点、格式、可能的错别字<br>3. 过长段落可整段进入一个单元格<br>4. 如有精简需要（过长），确保不改变原意，用 `...` 标注省略 |
| **来源文件** | 1. 使用反引号包裹文件名（如 `` `申报书.docx` ``）<br>2. 文件名**必须**与材料清单中的名称完全一致<br>3. 如有多个文件指向同一条证据，用 `、` 或 `；` 分隔 |
| **位置/章节** | 1. 优先使用文档内的章节标题层级路径<br>2. 格式如：`一、基本信息-项目名称` 或 `二、建设情况汇报-（四）应用场景层建设`<br>3. 如有页码可直接标注：`P12` 或 `第12页` |

### 5.3 特殊标记

| 标记 | 含义 | 用法 |
|------|------|------|
| ⚠️ | 警示/缺失 | 用于标注该字段尚为空、或找不到对应材料 |
| 🔴 / 🟠 / 🟡 / 🔵 | 严重性分级 | 用于产出物中的问题严重性标识 |
| `[原文如此]` | 保留原文 | 当原文有疑似错别字或不符合规范时使用 |
| `[sic]` | 原文如此 | 同上，拉丁文标记 |
| `---` | 分隔线 | 用于大板块之间的分隔，增强可读性 |

## 六、材料清单写法

材料清单是头部元信息的重要部分，按以下规范编写：

### 6.1 文件编号格式

按重要程度或引用频率排序，不要按文件名字母序。

### 6.2 文件说明要素

每个文件配一条简短说明，包括：
- **文件类型**（docx / pdf / md / xlsx 等）
- **核心内容**（一句话概括）
- **与本项目的关系**（如「这是本溯源库的主要证据来源」「这是空白模板」「这是平台能力的产出证据」）

### 6.3 示例

```markdown
> **材料清单**：
> 1. `申报表模板.docx` — 申报表原始空白模板（尚未填写）
> 2. `项目介绍.docx` — 申报单位及项目详细介绍
> 3. `XX大赛申报书.docx` — 此前参赛提交的申报书（内容高度相关）
> 4. `建设情况报告.docx` — 项目具体建设情况汇报
> 5. `用户手册.pdf` — 平台用户操作手册
> 6. `测试报告.md` — 项目测试验收报告（作为应用成效的产出证据）
```

## 七、质量检查清单

生成完溯源库后，逐项检查：

### ✅ 完整性检查

- [ ] 申报表的**每一个填写项**都在溯源库中有对应章节（或标注了缺失）
- [ ] 每条证据都标注了**来源文件**和**位置**
- [ ] 所有引用原文都加了**引号**
- [ ] 所有找不到的要点都用 ⚠️ **明确标记缺失**

### ✅ 真实性检查

- [ ] 原文**没有经过改写或润色**
- [ ] 没有**伪造或推测**原文中不存在的内容
- [ ] **错别字和格式问题**保留原样（可加 `[sic]` 标注）

### ✅ 可用性检查

- [ ] 材料清单中的文件名与表格中「来源文件」列的命名**完全一致**
- [ ] 章节编号**连续**、**无跳号**
- [ ] 文档头部的元信息（项目名称、日期等）填写完整
- [ ] 末尾有 **「材料问题标注」** 章节

### ✅ 格式检查

- [ ] 表格对齐（Markdown 中表现良好）
- [ ] 特殊标记（⚠️、--- 等）使用正确
- [ ] 板块间分隔线合理

## 附录：本模板的使用方法

当你以后新的申报项目需要生成成果溯源库时，操作流程如下：

1. **准备材料**：将所有原始材料收集到项目文件夹中
2. **提供模板**：把本说明文档发给 AI，附上以下信息：
   - 申报表的**章节结构**（或直接贴入空白申报表）
   - 原始材料的**文件清单**（名称 + 说明）
   - 要求按照本模板的规范生成溯源库
3. **迭代完善**：AI 生成初稿后，检查缺失项，补充材料重新提取
4. **使用**：溯源库完成后，申报表的每个字段都可以直接从对应表格中找到原文引用
