积水智能体技术方案

# 一、智能体架构

## 1.1 建设思路

系统采用分层解耦的架构设计，整体分为接入层、业务逻辑层和数据层三个层次：

接入层：负责接收气象预警信息、用户输入和外部 API 调用
业务逻辑层：包含 6 个核心智能体组件，形成完整的积水监测工作流
数据层：负责积水数据存储、摄像头信息管理、日志记录、报告存储等

## 2.2 核心组件

系统规划 6 个核心智能体组件，按工作流顺序排列：

1. 预警数据转写智能体：将气象预警文本转为结构化数据
2. 积水点位信息整理智能体：整理积水点位信息并截取视频流图片
3. 视频流判断智能体：分析视频流，判断是否存在积水情况
4. 图像特征物抓取智能体：从图像中识别和提取积水相关特征物
5. 处置力量判断智能体：根据积水情况判断所需处置力量
6. 报告撰写智能体：生成积水监测报告

## 2.3 数据流设计

### 2.3.1 完整工作流程

预期数据流：

Step 1：接收气象预警
预警数据转写智能体解析气象预警文本，提取结构化数据

Step 2：积水点位整理
积水点位信息整理智能体获取相关区域的摄像头列表并截取视频画面

Step 3：视频流判断
视频流判断智能体分析视频帧，判断是否存在积水

Step 4：特征物抓取
图像特征物抓取智能体识别图像中的积水相关特征物

Step 5：处置力量判断
处置力量判断智能体根据分析结果判断所需处置力量

Step 6：报告生成
报告撰写智能体整合所有分析结果，生成积水监测报告

### 2.3.2 智能体调用关系

6 个智能体按顺序串联，形成完整的工作流：

预警数据转写智能体 → 积水点位信息整理智能体 → 视频流判断智能体 → 图像特征物抓取智能体 → 处置力量判断智能体 → 报告撰写智能体

每个智能体的输出作为下一个智能体的输入或部分输入，形成数据传递链路。

# 三、智能体建设

在智能体建设阶段，需完成总体流程设计、功能模块设计、模块连接以及交互数据处理方式的统筹规划与设计工作，确保各模块之间的协同运作，该部分预计工作量为1.00人·月。

## 3.1 预警数据转写智能体

### 3.1.1 功能定位

该智能体预期将气象局发布的文本格式预警信息转换为结构化的数据库记录。利用大语言模型的文本理解能力，从非结构化的预警文本中提取关键字段，并映射到预定义的数据模型中。

### 3.1.2 输入输出设计

预期输入：
- 输入文本: 气象局预警信息（文本类型），如"无锡市气象台 2026 年 06 月 05 日 10 时 00 分发布暴雨蓝色预警信号"...

预期输出：
- 结构化的预警数据列表
- 写入是否成功
- 写入结果消息
- 日志标识

### 3.1.3 技术要点

1. 文本解析：使用大语言模型解析气象预警文本
2. 字段提取：提取预警类型、级别、发布时间、影响区域等关键字段
3. 格式映射：将提取的字段映射到标准数据格式
4. 数据写入：将结构化数据写入数据库

预警数据转写智能体的建设工作主要涉及对接气象接口获取实时预警数据、将非结构化的预警文本记录为结构化数据格式、以及调试大语言模型Prompt以准确解析和提取预警信息中的关键字段，预计工作量为1.00人·月。

### 3.2 积水点位信息整理智能体

### 3.2.1 功能定位

该智能体负责整理积水点位的基础信息，并从视频流中截取当前帧图片。预期对接视频云平台 API，通过摄像头编码列表获取实时画面，为后续的多模态分析提供图像数据。

### 3.2.2 输入输出设计

预期输入：
- 摄像头的列表

预期输出：
-积水点位信息列表，每个元素包含：
 - 区域名称
 - 街道名称
 - 摄像头编码
 - 位置描述
 - 截图 URL 地址

### 3.2.3 技术要点

1. 摄像头信息获取：从配置中读取指定区域的摄像头列表
2. 视频流接入：通过视频云平台 API 建立视频流连接
3. 截图生成：调用平台截图接口，生成当前帧图片
4. URL 拼接：根据平台规则生成图片访问 URL
5. 数据组装：将摄像头元数据与图片 URL 组装为结构化数据

积水点位信息整理智能体的建设需要完成获取预警信息后自动对接积水点位库、从点位数据中抽取行政区和街道信息、以及对接视频平台API拉取摄像头列表等功能的开发与调试工作，预计工作量为3.00人·月。

### 3.3 视频流判断智能体

### 3.3.1 功能定位

该智能体预期对视频流进行实时分析，判断是否存在积水情况。基于多模态大模型的视觉理解能力，对视频帧进行连续分析，识别积水存在的迹象。

### 3.3.2 输入输出设计

预期输入：
- 视频截图的 URL 地址
- 分析提示词

预期输出：
- 是否存在积水
- 置信度
- 判断依据描述

### 3.3.3 技术要点

1. 视频帧接入：支持单张或多张连续帧输入
2. 积水判断逻辑：分析路面水位、车辆通行情况等特征
3. 置信度评估：输出判断的可信程度
4. 阈值设定：调试积水判定阈值，平衡误报和漏报

### 3.3.4 多模态模型优势分析

传统视频分析方案在积水识别场景中存在明显局限：只能通过水面反光、颜色变化等浅层视觉特征判断"有无积水"，无法感知水深、无法利用场景中的参照物进行综合推断，且受雨夜环境影响误报率较高。多模态模型在本方案中相比传统方案具备以下核心优势：

参照物推断能力

多模态模型不仅能识别"积水"，更能理解积水和场景中其他物体的空间关系，从而做出更准确的判断：

- 车辆涉水深度：通过观察轮胎淹没高度、排气管位置、引擎盖是否浸水，推断实际水深和车辆通行风险

- 路面设施参照：利用路沿石淹没程度、绿化带灌木露出高度、路灯基座位置等固定参照物交叉估算积水深度

辅助处置力量决策

传统方案仅输出"有/无积水"的二元结果，对处置力量调度帮助有限。多模态模型能提供精细化的现场信息，直接支撑资源调配：

积水面积和深度估算：通过场景参照物估算积水范围和深度，辅助判断是否为积水

抗干扰能力强

雨天环境下传统 CV 方案容易将雨水反光、深色路面误判为积水。多模态模型可综合场景上下文进行判断，区分雨水反光与真实积水、区分深色路面与水体的视觉差异，夜间也可借助路灯倒影、车灯反射等辅助线索完成判断。

视频流判断智能体需实现抽取视频流进行实时截图、对截取图片进行黑屏判断以过滤无效帧、以及调试多模态模型分析画面中是否存在积水迹象等功能，预计工作量为1.50人·月。

### 3.4 图像特征物抓取智能体

### 3.4.1 功能定位

该智能体预期从图像中识别和提取与积水相关的特征物，如车辆淹没程度、行人涉水情况、路面淹没面积等。基于多模态大模型的物体检测和场景理解能力，提供细粒度的积水特征描述。

### 3.4.2 输入输出设计

预期输入：
- 图片的 URL 地址
- 需要识别的特征物类型列表

预期输出：
- 识别到的特征物列表，每个包含：
 - 特征物类型（车辆/行人/路面/其他）
 - 位置描述
 - 涉水程度描述
 - 识别置信度

### 3.4.3 技术要点

1. 特征物定义：预定义需要识别的特征物类型（车辆、行人、路面标志等）
2. 物体检测：使用多模态模型识别图像中的目标物体
3. 涉水分析：分析每个特征物的涉水程度
4. 位置标注：标注特征物在图像中的位置

图像特征物抓取智能体的开发工作包括调试多模态模型对积水相关的特征物进行准确识别、优化模型分析积水程度和特征物类型的能力，预计总工作量为3.00人·月。

### 3.5 处置力量判断智能体

### 3.5.1 功能定位

该智能体预期根据积水情况和特征物分析结果，判断是否需要处置力量及现场是否存在处置力量，防止二次上报。

### 3.5.2 输入输出设计

预期输入：
- 积水程度
- 影响区域描述
- 图像特征物分析结果

预期输出：
- 是否需要处置力量

- 现场是否存在处置力量

- 是否上报相关平台

### 3.5.3 技术要点

1. 规则引擎：预定义不同积水程度对应的处置标准
2. 现场处置力量：根据积水情况匹配所需的处置资源（人员、设备、车辆等）
3. 措施建议：生成具体的处置措施建议

处置力量判断智能体需实现调试模型对图片中的处置力量进行准确识别、根据积水程度和现场是否存在处置力量、以及对接相关处置平台接口进行工单派发等功能，预计工作量为3.00人·月。

### 3.6 报告撰写智能体

### 3.6.1 功能定位

该智能体预期整合前述各智能体的分析结果，生成结构化的积水监测报告。基于大语言模型的文本生成能力，将结构化数据转换为自然语言报告。

### 3.6.2 输入输出设计

预期输入：
- 预警数据
- 积水点位信息
- 视频流分析结果
- 图像特征物分析结果
- 处置力量判断结果

预期输出：
- 图文格式汇报

### 3.6.3 技术要点

1. 数据整合：汇总各智能体的输出结果
2. 模板匹配：根据报告类型选择合适的报告模板
3. 文本生成：使用大语言模型生成自然语言报告

报告撰写智能体的建设主要涉及调节报告模板文件以适应不同场景需求、设计结构化报告生成逻辑、以及确保各智能体分析结果能够整合为完整的图文汇报文档，预计工作量为0.50人·月。

## 3.7 Prompt 工程策略

### 3.7.1 Prompt 三层结构

每个大语言模型节点的 Prompt 设计可遵循统一的三层结构：

第一层：角色锚定
定义 LLM 的角色和核心任务，让模型理解自己的身份和职责范围。

第二层：强制规则
设定模型必须遵守的硬性约束，确保输出的合规性和安全性。

第三层：输出约束
定义输出格式和规范，确保下游系统能够正确解析模型输出。

### 3.7.2 Prompt 验证维度

每个 Prompt 可从以下四个维度进行验证：

边界测试：输入残缺信息、空值、极端长度、特殊字符时的表现。
拒答测试：输入模型知识库中不存在的信息，验证模型是否会编造答案。
格式测试：验证输出格式是否符合 Prompt 中定义的输出约束。

### 3.7.3 视频流判断 Prompt 示例

视频流判断 Prompt 可包含以下分析维度：

1. 积水存在性判断：图像中是否存在明显积水
2. 积水程度评估：无积水/轻微积水/中度积水/严重积水
3. 判断依据：列出判断积水存在的关键视觉特征

输出格式可设计为 JSON 结构。

### 3.7.4 特征物抓取 Prompt 示例

特征物抓取 Prompt 可包含以下强制规则：

- 识别指定的特征物类型（车辆、行人、路面标志等）
- 描述每个特征物的涉水程度

### 3.7.5 报告撰写 Prompt 示例

报告撰写 Prompt 可包含以下结构要求：

1. 预警概况：简述气象预警信息
2. 积水点位情况：列出各积水点位的分析结果
3. 特征物分析：描述识别到的积水相关特征物
4. 处置力量情况：现场是否存在相关处置力量
5. 平台上报：上报处置平台的积水点位

# 四、知识库建设

### 4.1 重点积水点位数据整编

针对全市重点积水点位开展全流程数据治理工作，整体工作量0.61 人・月，严格按照数据业务流程分步实施：

1.数据归集：全面收集点位地址、关联摄像头、设备编码等多源基础信息，完成原始数据统一汇总；

2.清洗治理：对重复、缺失、异常数据进行剔除、补全与修正，统一字段格式与数据口径；

3.数据标注：结合业务规则完成积水点位属性、摄像头对应关系等内容标准化标注；

4.数据质检：开展全量数据抽样核验与完整性、准确性校验，剔除不合格数据。 通过全流程治理建成标准化积水点位专题数据库，为积水智能体系统稳定运行提供可靠、高质量基础数据支撑。
